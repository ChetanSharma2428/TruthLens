# TruthLens — UI/UX Design System

## 1. Design Goal

TruthLens must look like a **real information-review product**.

The visual language should feel:

- Credible.
- Calm.
- Editorial.
- Structured.
- Transparent.
- Professional.

It should not look like a generic "AI SaaS" template.

## 2. Avoid

Do not use:

- Excessive gradients.
- Neon/glowing UI.
- Random glassmorphism.
- Huge decorative AI illustrations.
- Excessive rounded cards.
- Fake metrics.
- Fake partner logos.
- Every section inside a floating card.
- Animations without a product purpose.

## 3. Visual Hierarchy

The primary visual hierarchy is:

```text
Page purpose
    ↓
Claim content
    ↓
Status / Risk
    ↓
Supporting metadata
    ↓
Actions
```

Claim text is the most important content in the feed and detail pages.

## 4. Color Semantics

Use restrained semantic colors:

| Meaning | Semantic treatment |
|---|---|
| Verified True | Positive |
| False | Negative |
| Misleading | Warning |
| Unverified | Neutral |
| High Risk | Strong warning |

Never communicate status through color alone. Always show a text label.

## 8. Submit Claim Page

Use a focused form.

```text
Submit a Claim

Claim
[ multiline input ]

Source Platform
[ WhatsApp ▼ ]

Category
[ Finance ▼ ]

Source Link (optional)
[ URL ]

[ Submit Claim ]
```

Include:

- Field labels.
- Required indicators.
- Helpful errors.
- Disabled submit while sending.
- Success state.

## 9. Claim Detail Page

Use an editorial record layout:

```text
← Back to Claims

FALSE

Full claim text

Source Information
Risk Analysis
Verification
Timeline
```

The reviewer note should have strong visual separation.

## 10. Reviewer Access

Minimal:

```text
Reviewer Access

Authorized review workspace.

Reviewer Code
[________________]

[ Continue ]
```

Avoid calling this "Login" or "Sign Up."

## 11. Reviewer Dashboard

Top:

```text
Reviewer Workspace

12 claims awaiting review
```

Queue should emphasize:

- Risk.
- Claim.
- Category.
- Platform.
- Submission time.
- Review action.

## 12. Review Panel

Separate three concepts:

### Claim

Exact submitted content.

### Automated Risk Analysis

Flags generated by the required rules.

### Reviewer Decision

Verdict + explanation.

This separation is critical for product credibility.

## 13. Responsive Design

### Desktop

Use generous whitespace and a structured content column.

### Tablet

Collapse secondary columns where necessary.

### Mobile

- Stack filters.
- Full-width cards.
- Readable claim text.
- No horizontal scrolling.
- Large enough tap targets.

## 14. Interaction

Use subtle transitions for:

- Button hover.
- Focus.
- Card interaction.
- Filter changes.
- Modal/panel opening.

Avoid excessive animation.

## 15. Accessibility

Every important control needs:

- Semantic HTML.
- Keyboard access.
- Visible focus state.
- Associated label.
- Readable contrast.
- Text status labels.

## 16. Component Styling

Every component owns its CSS:

```text
Component.jsx
Component.css
```

Pages compose components rather than duplicating component styles.

## 17. UI States

Design explicitly for:

```text
Default
Hover
Focus
Loading
Success
Error
Empty
Disabled
```

## 18. Credibility Rules

Never fabricate:

- Accuracy percentages.
- Number of users.
- Number of verified claims.
- Government endorsements.
- Newsroom partnerships.

Realistic design means believable information architecture, not invented proof.
